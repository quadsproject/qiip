### Power State Badge Color Mapping

| Power State | Badge Class | Color | Semantic |
|-------------|-------------|-------|----------|
| On | `badge-complete` | `var(--success)` green | Node powered on |
| Off | `badge-failed` | `var(--danger)` red | Node powered off |
| Unknown | `badge-unknown` | `var(--warning)` amber | State undetermined or fetch failed |

**CORRECTION from CONTEXT.md D-03:** The context document specifies `badge-in-progress` for Unknown and labels it "amber". However, `badge-in-progress` actually renders as **blue** (`var(--primary)`). The class that renders **amber** (`var(--warning)`) is `badge-unknown`. Since the user's stated intent is amber for unknown power state, use `badge-unknown` instead of `badge-in-progress`. All other D-03 mappings (On = `badge-complete`, Off = `badge-failed`) are correct.

Accent reserved for: nav link hover states, "Back to fleet" link, action buttons with `.btn-setup` class. Not used for power state badge.

## Component Inventory

This phase introduces zero new components. It adds one DOM element using existing patterns.

### Power State Badge

**HTML structure** (added to `node_detail.html` header, after `<p id="node-state">`):
```html
<p id="power-state" style="margin:0.25rem 0 0 0">
  <span class="badge badge-unknown">Power: Unknown</span>
</p>
```

**Initial state:** Renders "Power: Unknown" with `badge-unknown` (amber) as placeholder while fetch is in flight.

**JS function:** `refreshPowerState()` in `node_detail.js`
- Calls `GET /admin/nodes/{NODE_ID}/power`
- Response shape: `{ hostname: string, power_state: string }`
- Maps `power_state` to badge class and label:
  - `"On"` -> class `badge-complete`, text `"Power: On"`
  - `"Off"` -> class `badge-failed`, text `"Power: Off"`
  - Any other value or fetch error -> class `badge-unknown`, text `"Power: Unknown"`
- Updates `#power-state span` className and textContent

**Lifecycle:**
- Called once on `DOMContentLoaded` (after existing `refreshDetail()` call)
- NOT added to the `setInterval(refreshDetail, POLL_INTERVAL_MS)` loop (decision D-04)
- Exported as standalone function for Phase 34 to call after power actions

## Interaction States

| State | Visual | Trigger |
|-------|--------|---------|
| Loading | `badge-unknown` "Power: Unknown" | Page load, before API response |
| Power On | `badge-complete` "Power: On" | API returns `power_state: "On"` |
| Power Off | `badge-failed` "Power: Off" | API returns `power_state: "Off"` |
| Unknown | `badge-unknown` "Power: Unknown" | API returns other value |
| Fetch error | `badge-unknown` "Power: Unknown" | Network error or non-200 response |

No loading spinner. No skeleton. The badge starts as "Power: Unknown" and resolves within the single fetch. This matches the existing pattern where `<p id="node-state">` shows "Loading..." then updates.
