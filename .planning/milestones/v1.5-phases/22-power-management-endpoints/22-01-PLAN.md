<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> admin API | Hostname path parameter and action request body cross trust boundary |
| admin API -> BMC | RedfishClient forwards requests to BMC over HTTPS (handled in Phase 21) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Tampering | hostname path param | mitigate | canonical_hostname() normalizes input before BMC resolution (D-02); BMC host template constrains target to mgmt-{hostname} pattern |
| T-22-02 | Tampering | action request body | mitigate | Pydantic PowerAction(str, Enum) rejects invalid values with 422 before reaching RedfishClient |
| T-22-03 | Information Disclosure | error responses | mitigate | RedfishError.human_message is pre-sanitized in Phase 21 (extract_error_message truncates to 200 chars, maps to friendly text); no raw BMC JSON leaked |
| T-22-04 | Denial of Service | POST power action blocking | accept | POST blocks until poll completes (up to 60s default). Acceptable for internal admin API with low request volume. No auth in v1 per CLAUDE.md constraint (internal network only). |
| T-22-05 | Spoofing | no authentication | accept | Internal network only, no external-facing endpoints in v1 (CLAUDE.md constraint). Auth is out of scope per ASVS V2/V4 assessment in RESEARCH.md. |
</threat_model>
