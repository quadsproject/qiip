## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /admin/models/download | Operator submits repo_id via JSON body |
| client -> GET /admin/models/downloads | Operator queries download statuses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-05 | Spoofing | POST /admin/models/download | accept | Internal network only per project constraints -- no auth in v1 admin API (consistent with all other admin endpoints) |
| T-31-06 | Tampering | repo_id in POST body | accept | Pydantic validates type; snapshot_download validates repo format server-side; no path construction in gateway code |
| T-31-07 | Information Disclosure | GET /admin/models/downloads | accept | Returns status and error strings only -- no secrets, tokens, or internal paths exposed |
| T-31-08 | Denial of Service | POST flood | mitigate | Semaphore(2) in DownloadService caps actual downloads; duplicate POSTs return existing status (D-10) without spawning new work |
</threat_model>
