<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> API routes | Client-supplied model name flows into NodeSelector.select() and error messages |
| etcd watcher -> registry | DELETE events trigger drain transitions; compromised etcd could trigger premature draining |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Tampering | routes.py connection tracking | mitigate | try/finally block ensures decrement always fires after increment, preventing counter leak on exceptions. Streaming generator also uses try/finally for its decrement path. |
| T-04-06 | Denial of Service | watcher drain | accept | Malicious etcd DELETE events could drain all nodes, but etcd is on internal network with controlled access. No additional mitigation needed for v1. |
| T-04-07 | Information Disclosure | model_not_found_error | accept | Error message echoes client-supplied model name. Internal network only; no sensitive data leak. |
| T-04-08 | Elevation of Privilege | get_node_selector DI | accept | DI function reads from app.state set during lifespan. No user input influences dependency resolution. |
| T-04-09 | Tampering | _maybe_remove_drained | mitigate | Only removes node when both conditions met: status is DRAINING (set by etcd DELETE, not client input) AND connection count is 0 (managed by try/finally, not client input). Race between concurrent requests is safe because tracker uses threading.Lock and registry.remove is idempotent. |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this plan. |
</threat_model>
